# Product Brief

One page the whole studio can repeat back: the problem, who has it, and how we'll know it's working. **@The Product Lead** drafts it, **@The App Developer** builds against it, and **@The QA Reviewer** turns the success metric into the acceptance checklist.

## Problem

What's broken, annoying, or missing — for whom — in one paragraph. Write it the way you'd say it to a friend, not the way you'd say it in a pitch.

> Example: Freelancers lose half an hour a week re-typing the same client update, because the tool they use makes them start from a blank box every time.

## Users

- **Who specifically**: the one or two people this is for first. "Everyone" is a scope bug, not an audience.
- **Where they are now**: what they do today, and the two things that already almost work.
- **What they'd pay**: money, time, or attention — name which.

## Success metric

One number, one threshold, one date — nothing else counts as success:

- **Metric**: e.g. "first update sent within five minutes of sign-up".
- **Threshold**: e.g. "70% of new users in their first week".
- **By**: [date].

If the metric needs a dashboard nobody has, note that as an open item rather than lowering the bar.

## Scope

- **In for v1**: the smallest version that proves the point — one sentence per item.
- **Explicitly out**: what you are *not* doing, so nobody re-litigates it next week.

## Ready to start? Three openers to try

1. `@The Product Lead — turn this idea into a one-sentence problem, the first user, and the smallest version worth shipping.`
2. `@The QA Reviewer — write the acceptance checklist for [feature] before a line is written.`
3. `@The App Developer — build [feature] against that checklist and say what's at risk.`

## Working notes

- The nightly standup writes itself — read it in #standup each weekday morning; there's nothing to fill in.
- This studio ships **without skills on purpose** — lean is the point. When the same how-to shows up twice (a deploy checklist, a review ritual, a fixture recipe), write it up as a skill and bind it to your agents; you can add one later without changing anything here.
