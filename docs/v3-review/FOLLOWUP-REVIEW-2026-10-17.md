# Follow-up review of D49–D53 — 17 October 2026

> **History (review record), 2026-10-31.** Its findings were acted on at the time; the raise it reviews waits for the audit (D137). The current index is [STATUS.md](STATUS.md).

Reviewed commits `717457c09..38baf1258` against the earlier product findings, with existing uncommitted work preserved. This review checks the prior fixes and material defects in the new recovery, exit and spending workflows. It is not an audit of unchanged contracts or a hosted-deployment approval.

**What improved**

The normal milestone cancellation/reload path now preserves its claim ID and evidence and resumes the missing operation. Evidence has a launch-specific read and an explicit read-error state. Pending-bond read failures have a retry; unlocked launches receive different allocation/powers text. Backers can see panel terms and continuity risk. The homepage now leads with backing teams and milestone accountability.

The strongest product addition is the distinction between reviewed work budgets and direct treasury payments, together with actual freeze, unwind, slash and close-budget decisions. Starting a dispute from the claim is a useful improvement. The exit calculation now correctly reads supply from the token contracts, excludes DAO-held Shares/non-voting shares, and burns only free Shares. Moving protocol details under an expandable section and simplifying the bid dialog improve the primary backer path.

**Findings to fix before a public tester cohort**

1. **[P1] Exit must wait for the sale currency to be resolved.** [RagequitPanel.tsx:123](../../web/src/features/launchpad/ui/RagequitPanel.tsx#L123) reads the auction currency separately, but lines 142–144 substitute an ETH-only token list while that read loads, fails or returns malformed data. The position query and exit remain independently available. An otherwise valid USDC-funded DAO can consequently offer a burn of all free Shares with no USDC in the payout list. The contract burns the ownership once and pays only the named assets, so this can permanently surrender the omitted entitlement. Block position/exit readiness until a known auction's currency is successfully resolved; treat malformed replies as errors and provide Retry. Exercise slow, rejected and malformed currency reads before allowing any burn.

   Related amount correction: [fetchTokenInfo:96](../../web/src/features/launchpad/lib/ragequit-position.ts#L96) and the panel's `infoOf` assume 18 decimals if metadata is unavailable. A six-decimal token can then be displayed a trillion times too small. Show unavailable metadata or explicitly raw units rather than inventing a scale.

2. **[P1] Slashing must include bonds waiting to be withdrawn.** [SlashForm:218](../../web/src/features/launchpad/ui/enforcement-forms.tsx#L218) filters and caps using active reviewer stake only. [VerifierSet.requestUnbond:202](../../contracts/src/VerifierSet.sol#L202) removes that stake immediately, while the pending amount remains slashable under [slash:224](../../contracts/src/VerifierSet.sol#L224). A reviewer requesting their entire bond back disappears from the form during the very period intended for accountability. Read active and pending amounts per reviewer, include both in the available slash amount, and display the pending withdrawal deadline. Cover full and partial unbonding and unreadable pending amounts.

3. **[P1] The aggregate runner must not stop or delete unrelated development work.** [mvp-gate.sh:47](../../scripts/mvp-gate.sh#L47) kills every matching forked Anvil, every matching port-18xxx Anvil, and processes connected to port 4173, regardless of ownership. Its [exit trap:24](../../scripts/mvp-gate.sh#L24) removes all global Anvil state directories newer than a marker, including another concurrently running task's newly saved state. Track the PIDs and state paths owned by this invocation, allocate ports or fail with an actionable busy-port message, and preserve all unrelated processes/state. The aggregate runner was not executed during this review; the economy script was invoked directly on its own port and scratch database.

4. **[P2] Spending summaries need truthful incomplete/unknown accounting.** [spending.ts:200](../../packages/creaton-core/src/launchpad/spending.ts#L200) ignores `work.truncated`, so capped mandate/claim history can appear complete. Its headline at line 205 claims both reviewed and direct payments whenever unknown executions exist, even when both classified totals are zero. Its closed-budget accounting at line 136 counts unbound Frozen claims' requested amounts as commitments. Production-helper checks reproduced all three cases, including a budget of 100 reporting 1,000 committed from an unbound request. Carry work and decision completeness separately, describe unknown executions as unknown, and count actual bound/reserved commitments. Correct the existing test that endorses the unknown-only false headline.

5. **[P2] Closing a budget must disclose the effect on unawarded Shares.** [CloseBudgetForm:181](../../web/src/features/launchpad/ui/enforcement-forms.tsx#L181) and [closeBudgetDecision:548](../../packages/creaton-core/src/launchpad/daoActions.ts#L548) describe stopping new claims and preserving funded claims' rules. Closing also disables every later Shares award through that mandate, including paid/approved work awaiting its award ([consumeContribution:272](../../contracts/src/TreasuryMandate.sol#L272)). Explicitly show that consequence before the vote; distinguish continuing currency-escrow settlement from losing access to an unconsumed Shares allowance.

6. **[P2] A claim-specific dispute must not silently choose another claim.** [ClaimPickForm:75](../../web/src/features/launchpad/ui/enforcement-forms.tsx#L75) falls back to the first eligible claim when the explicitly requested claim is missing or changes state. A user opening “freeze A” can therefore arrive at a draft for B. Preserve the requested target; if unavailable, explain why and require an explicit new choice. Cover a claim becoming Paid or otherwise ineligible between opening the claim card and loading the form.

7. **[P2] Submission persistence failures must stop before transactions begin.** [saveSubmission:123](../../web/src/features/launchpad/lib/milestone-submission.ts#L123) catches storage failures and returns normally; [MilestoneRow:245](../../web/src/features/launchpad/ui/MilestoneRow.tsx#L245) continues sending. An injected quota failure reproduced a successful-looking save followed by no draft on reload, recreating the previous lost-ID/evidence problem. Return a durable-save result and block the first transaction when it fails, with a recoverable message or explicit alternative export.

8. **[P2] Bond metadata failures still hide the return surface.** [readBond:163](../../packages/creaton-core/src/launchpad/workRead.ts#L163) turns failures at `bondToken()` or `minBond()` into `bond: null`. The improved pending-bond reader is skipped when bond metadata is null, and the return component is hidden. Distinguish a confirmed bond-free/legacy panel from unreadable modern metadata, and expose Retry. Test these metadata failures in addition to the now-covered `unbonds()` failure.

9. **[P2] Launch-scoped evidence still has a same-launch history cutoff.** [evidenceQueryFilter:18](../../web/src/features/launchpad/lib/evidence-query.ts#L18) reads only the newest 500 launch updates. An outstanding packet behind 500 newer updates from the same project becomes unavailable to reviewers again. Query outstanding claim packets specifically, or page bounded history while explicitly reporting incompleteness. Add a case with an outstanding packet behind 501 newer same-launch updates.

**Validation and release interpretation**

The skipped wallet-helper test requires Anvil on its invoking shell's PATH. Auction/governance/challenge clocks were advanced by the test. This confirms those integrated paths with successful reads; it does not cover the degraded-read and pending-withdrawal cases above.

Focused browser smoke checks for the homepage, launch page and auction screens: 44 passed, six chain-dependent cases skipped in the default smoke configuration. The real economy journey above ran separately with its required local infrastructure.

The aggregate runner is a useful local entry point, but it is not currently an enforced CI gate and does not enumerate every existing journey. Public hosting, actual passkey bundler acceptance, independent security review and a production trading venue remain separate evidence requirements. These updates do not implement CREATE; they strengthen the fundraising-and-delivery MVP.
