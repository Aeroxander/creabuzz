## Facts that changed the drafts

- The old privacy note said logs with IP addresses are kept for 30 days. The relay logs show the proxy's address, there is no web server access log, and logs are kept by size (five files of 10 MB per service). Rewritten.
- The old note said a passkey keeps the key. That is true only when the device supports key derivation. Rewritten.
- The security record (one row per stored item, with the sending account) was not mentioned and is now.
- Backups hold the server's settings and secrets. In round one the script did not encrypt them, and the note said so. Counsel called that a fix-this, not a disclose-this (N2): since 35ed13b the script encrypts each backup to a public key (`deploy/compose/backup.sh:65` and `:183`) and the note now says that.
- Reports can reach the server owner. Now said.
- The brackets guard used to read one line at a time, so a bracket that ran over two lines in the old drafts (for example the abuse email and the backup location) was not caught. All brackets were put on one line, and the guard now reads the whole file (8fa4cc1), so it also catches a lone `[` or `]`.
