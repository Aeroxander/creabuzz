## Key Patterns (Must Follow)

### Signing events
```ts
import { signRelayEvent } from "@/shared/api/tauri";
import { relayClient } from "@/shared/api/relayClient";

const event = await signRelayEvent({ kind, content: JSON.stringify(...), tags });
await relayClient.publishEvent(event, "Timed out ...", "Failed to ...");
```

### React Query mutations
```ts
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { orgQueryKey } from "../hooks";

export function useMyMutation() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: async (input) => { /* sign + publish */ },
    onSuccess: async () => {
      await queryClient.invalidateQueries({ queryKey: [...orgQueryKey, "relevant-key"] });
    },
  });
}
```

### Forms (no react-hook-form, no zod)
- Custom hook with `useState` + `useEffect` for reset on dialog open
- Manual `handleSubmit` with try/catch, error state, `canSubmit` computed boolean
- `Input`, `Textarea`, `Button` from `@/shared/ui/`
- `<label>` for actual inputs; `<span>` for button group labels
- `<fieldset>` with `aria-labelledby` for grouped controls

### Dialogs
- `Dialog` (Radix) + `ChooserDialogContent` or `DialogContent` layout
- Controlled `open` prop, `onOpenChange` guards against close while submitting
- Close-on-success: `onOpenChange(false)` in the mutation's onSuccess

### Biome lint rules to watch
- Use `<span>` not `<label>` when no associated `<input>`
- Use `<fieldset>` not `<div role="group">`
- Stable keys for dynamic lists (unique ID, not array index)
- No `unwrap()` / `expect()` in production paths
- No `unsafe` code
- No comments unless asked

## Phase 2: Grant Chain Visualization + Budget Consumption Dashboard

### 2.1 Grant Chain Viewer

**Goal**: Replace flat grant list with a hierarchical chain view.

**New file**: `desktop/src/features/org/ui/OrgGrantChainView.tsx`

**Data**: `useOrgGrantsQuery()` → `buildGrantTree()` (already in `lib/tree.ts`,
currently unused).

**UI**:
- Indented tree (same pattern as node tree in `OrgTreeNodeRow`)
- Root grants (depth 0) shown with solid left border
- Delegated grants (depth > 0) indented with dashed border
- Each row: verb badges, truncated grantee pubkey, expiry date
- Attenuation indicator: green check if child verbs ⊆ parent, red warning if
  violation
- Click to expand/collapse children
- Context menu: Revoke, Copy ID

**Violation detection** (client-side):
```
For each child grant:
  childVerb ∈ child.verbs
  parentVerb ∈ parent.verbs (walk up parentGrant chain)
  if childVerb has no matching parentVerb → violation
```
This mirrors the SDK's `verify_grant_chain()` logic from
`buzz-sdk/src/builders.rs:3000+`.

**Files to modify**:
- `desktop/src/features/org/ui/OrgChart.tsx` — replace `OrgGrantSection` with
  `OrgGrantChainView`
- `desktop/src/features/org/lib/tree.ts` — `buildGrantTree()` already exists,
  just import and use

### 2.2 Budget Consumption Dashboard

**Goal**: Show current usage vs limits per budget.

**Data challenge**: The relay has `budget_consumption` table (migration 0047)
but no WS/HTTP endpoint exposes it yet.

**Ship now (Option A)**: Compute from agent turn metric events (kind:44200).
- Query: `relayClient.fetchEvents({ kinds: [44200], "#p": [subjectPubkey], limit: 500 })`
- Filter by time window (day/week/month from `budget.window`)
- Count events in window → that's `consumed`
- Compare to `budget.limits.runs` → that's `percentage`

**Upgrade later (Option B)**: When relay exposes `budget_consumption` table
via API, swap the hook implementation.

**New hook** in `hooks.ts`:
```ts
export function useBudgetConsumptionQuery(
  subject: string,
  window: BudgetWindow,
  limit: number | undefined,
)
```
Returns `{ consumed: number, limit: number, percentage: number }`.

**New component**: `desktop/src/features/org/ui/OrgBudgetConsumption.tsx`
- Renders `<Progress>` bar from `@/shared/ui/progress`
- Color: green (<60%), yellow (60–80%), red (>80%)
- Text: "80 / 100 runs used"
- Tooltip: window reset time

**Files to create**:
- `desktop/src/features/org/ui/OrgBudgetConsumption.tsx`

**Files to modify**:
- `desktop/src/features/org/hooks.ts` — add `useBudgetConsumptionQuery`
- `desktop/src/features/org/ui/OrgChart.tsx` — embed `OrgBudgetConsumption`
  in budget cards

### 3.2 Review Workflow UI

**Goal**: Verifiers can accept/reject contribution records.

**Mechanism**: Publishing a new kind:37013 event with same d-tag and updated
`review_status` (NIP-33 LWW by `created_at`).

**New mutation** in `hooks.ts`:
```ts
export function useUpdateContributionReviewMutation()
```
- Takes `{ dtag, reviewStatus: ReviewStatus, appealNote?: string }`
- Fetches current record via `relayClient.fetchEvents({ kinds: [37013], "#d": [dtag] })`
- Copies all fields, updates `review_status`, appends to `appeal_history` if appeal
- Re-signs and publishes

**UI in detail drawer**:
- "Accept" button (green) — sets status to `accepted`
- "Reject" button (red) — sets status to `rejected`
- "Appeal" button (yellow, only if rejected) — sets status to `appealed`, prompts for note
- Confirmation dialog before accept/reject

**Access control**: Application-level only. Any signer can review. Future:
check for `review` verb grant in org chart.

**Files to modify**:
- `desktop/src/features/org/ui/ContributionRecordsTable.tsx` — add review buttons
- `desktop/src/features/org/hooks.ts` — add `useUpdateContributionReviewMutation`

## Open Questions for Implementer

1. **Grant chain**: Should attenuation violations block creation (relay-enforced)
   or just warn (client-side)? Currently the SDK checks but the relay doesn't
   enforce it.

2. **Budget consumption**: Kind 44200 events may not exist yet if no agents
   have run. The consumption dashboard should show "0 / N runs" gracefully.

3. **Contribution record review**: Should we gate review buttons behind a
   "verifier" grant check, or leave it open to all signers for now?

4. **Onboarding wizard**: Should it persist "completed" state (localStorage)
   or re-show on every empty-chart visit?

5. **Member sidebar badge**: This touches a different feature area
   (`features/channels/`). Consider whether to include in Phase 4 or defer
   to avoid scope creep.
